Classes of anomalies: lexical error, missing records, irregularities short · 6 reviews
  • Syntactically dirty data: lexical errors (structure of the data does not match the documented format, e.g. a row with 5 columns instead of 6), domain format errors, and irregularities (non-uniform use of values, units or abbreviations).
  • Semantically dirty data: integrity constraint violations, business rule contradictions, duplicates, invalid tuples.
  • Coverage anomalies: missing attributes (values) and missing tuples (whole records never captured).
Typical wording: two statements are given and you name the class. “Lexical error” → syntactic. “Missing records” → coverage.
Quality Management Maturity Grid: name the stage for each statement long · 5 reviews
Crosby's five stages, in order:
  1. Uncertainty: management has no comprehension of quality as a management tool; problems are blamed on others; “we don't know why we have problems”.
  2. Awakening: quality management is recognised as possibly valuable but nobody will fund it; “is it absolutely necessary to always have problems?”
  3. Enlightenment: management learns and commits; a formal quality programme starts; problems are resolved openly.
  4. Wisdom: defect prevention is routine; management participates personally; “we identify and resolve problems”.
  5. Certainty: quality is an integral part of the organisation; “we know why we do not have problems”.
Memory hook: U-A-E-W-C. In the paper a table of 4 statements is given and you write the matching stage next to each.
Kimball's lifecycle: phases and the three parallel tracks short · 5 reviews
  1. Project planning
  2. Business requirements definition
  3. Three parallel tracks:
    • Technology track: technical architecture design → product selection and installation.
    • Data track: dimensional modelling → physical design → data staging (ETL) design and development.
    • Application track: end-user application specification → end-user application development.
  4. Deployment
  5. Maintenance and growth
Project management runs across all phases. When asked for “five phases”, give planning, requirements, the three tracks (design/development), deployment, maintenance and growth.
ERD: relationship between Farmer and Field (Agri-DWH case study) short · 5 reviews
A diagram is given and you identify the relationship type. Farmer–Field is one-to-many: one farmer owns many fields, each field belongs to one farmer. Be ready to read crow's-foot notation: a single bar = one, a crow's foot = many, a circle = optional. Also expect “identify the entities” (Farmer, Field, Crop, Pest, Scouting visit).
Clustering: two types, and K-means steps short · 4 reviews
Two types: hierarchical (agglomerative: start with every point as its own cluster and merge; divisive: start with one cluster and split) and partitional (K-means: a fixed number K of flat clusters).
K-means: (1) choose K and pick K initial centroids, (2) assign each record to the nearest centroid, (3) recompute each centroid as the mean of its members, (4) repeat 2–3 until assignments stop changing. Weakness: you must pick K, and the result depends on the starting centroids and on outliers.
DTS: tools and package items short/long · 4 reviews
DTS (Data Transformation Services) in SQL Server 2000.
Tools: DTS Import/Export Wizard (quick copy of tables, query results or objects between sources), DTS Designer (graphical building of complex packages), and the DTS run utilities (dtsrun / dtsrunui) for executing saved packages.
Package items: connections (data sources and destinations), tasks (units of work such as Execute SQL, Transform Data, Bulk Insert, Send Mail), transformations (column-level changes applied while copying), and workflow (precedence constraints: on success, on failure, on completion).
Import/Export Wizard load tasks: copy whole tables, copy the result of a query, copy objects and data between SQL Server databases.
Barriers to linear speedup, Amdahl's law, speedup numerical short/long · 4 reviews
Barriers: startup (time to start many parallel processes), interference (processes competing for shared resources such as memory, bus or disk), skew (uneven work, so the slowest partition sets the finish time).
Speedup = time on the small system ÷ time on the large system. Linear when doubling hardware halves the time. Scale-up = bigger job on bigger hardware in the same time.
Amdahl's law: speedup = 1 / ((1 − f) + f / N), where f is the parallelisable fraction and N the processors. Max speedup = 1 / (1 − f). Example: f = 0.8, N = 4 → 1 / (0.2 + 0.2) = 2.5; with unlimited processors → 5.
Parallel hardware architectures short · 2 reviews
  • Symmetric multiprocessing (SMP): shared memory, shared disk, one OS image; easy to program, limited by the shared bus.
  • Distributed memory / MPP (shared nothing): each node has private memory and disk, nodes talk over an interconnect; scales the furthest.
  • NUMA: shared address space but memory access time depends on where the memory sits.
  • Clusters (shared disk): independent machines sharing storage.
Indexes: dense vs sparse, clustered index on Age, hash join cost short/long · 5 reviews
Dense index: an entry for every record. Sparse: one entry per block, pointing at the first record of the block; smaller, but the block must be scanned. A sparse index is only possible when the file is sorted on the key.
Clustered index on Age: physically sort the table by Age, then build the index with one entry per distinct Age (or per block) pointing at the first row with that value. Only one clustered index per table.
Nested-loop join variants: naive, index-based, temporary-index. Hash join: partition (build) phase hashes the smaller table into buckets; probe (matching) phase hashes each row of the larger table and compares only within the matching bucket. Practise the handout's cost example so you can plug in numbers.
Statistics vs data mining long · 2 reviews
  • Statistics: confirmatory, tests a hypothesis stated in advance, usually on a sample, needs a trained analyst to formulate the model.
  • Data mining: exploratory, generates hypotheses by discovering patterns in the full (large) data set, largely automated, aimed at business users.
  • Both use overlapping techniques (regression, clustering); the difference is the goal and the scale of data.
Web warehousing: page dimension attributes, web scraping, search methods short/long · 5 reviews
Page dimension attributes: page key, page source, page function (home, product, checkout…), page template, item type, graphics type, animation type, sound type, page file size.
Why scrape the web: the web is the largest data source about customers, competitors and markets, but it is unstructured and changes constantly. Sources: competitor sites, price listings, news, product catalogues, social/forum pages. Issues: junk data, layouts change, no fixed schema, legal/ethical limits.
Search methods: crawler-based search engines (spiders index pages), human-edited directories, and meta-search engines that query several engines at once.
Data quality: validation techniques, Orr's laws, TQM, data quality life cycle short/long · 5 reviews
Validation techniques: referential integrity checks, attribute domain checks, data quality rules, data histograms (frequency distributions). Not indexes.
Orr's laws: data that is not used cannot be corrected; data quality is a function of its use, not its collection; data will be no better than its most stringent use.
TQM brings product quality, process control and continuous quality improvement together; quality means conformance to requirements, and the requirements can themselves be defective.
Data quality project / life cycle: establish the quality goals and metrics → assess (profile) the current data → analyse the root causes → clean and correct → prevent at the source → monitor continuously. Check the exact step names against the handout lecture on data quality management.
Five types of partitioning, DWH implementation strategies, development methodologies long · 3 reviews
Partitioning (horizontal splitting, handouts pages 66–67): range, expression, round-robin, hash and list partitioning. Range and expression are the most common in warehouses; round-robin balances load but cannot prune partitions.
Implementation strategies: top-down (Inmon: enterprise warehouse first, marts fed from it), bottom-up (Kimball: marts first, integrated through conformed dimensions), and the hybrid approach.
Development methodologies: waterfall (poor fit, requirements are not known up front), spiral / iterative (recommended: deliver in increments), RAD and prototyping. Planning and design phase points: define scope and sponsor, identify business processes, choose grain, dimensions and facts, size the data, plan ETL, plan for growth.
